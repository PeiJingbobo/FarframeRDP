# Release 本地网络权限人工验证

## 范围

验证正式 Release 构建在首次连接局域网内的远程桌面主机时，会显示 macOS 本地网络访问授权，并在允许后继续发起 RDP 连接。

## 前置条件

- macOS 15 或更高版本，已登录且桌面会话已解锁。
- 从本任务生成的 DMG 安装 Farframe RDP。
- 一台位于同一局域网、由测试人员提供且允许测试的 Windows RDP 主机。
- 使用虚构测试账户或专用测试账户；不要在截图或日志中记录地址、用户名、密码或证书内容。
- 系统此前没有为 `com.farframe.rdp` 保存本地网络授权；如已有记录，在“系统设置 → 隐私与安全性 → 本地网络”中先移除或重置测试状态。

## 环境

- 构建类型：Release、Universal（arm64 + x86_64）、临时签名、未公证。
- App Bundle ID：`com.farframe.rdp`。

## 操作与预期结果

1. 打开 DMG，将 App 拖入“应用程序”，再从“应用程序”启动。
   - 预期：App 正常启动；未公证构建可能需要通过 Finder 的“打开”确认。
2. 新建一个指向局域网测试主机的连接并保存。
   - 预期：主机资料出现在列表中，密码只在选择保存时进入钥匙串。
3. 点击连接，或等待自动可达性检查首次访问局域网。
   - 预期：macOS 显示 Farframe RDP 的“本地网络”授权提示，说明文字为“Farframe RDP 需要访问本地网络，以连接您选择的远程桌面电脑。”
4. 点击“允许”。如服务器证书尚未受信，再按测试策略确认服务器证书。
   - 预期：网络访问不再因本地网络隐私策略被阻止；RDP 会话继续进入认证并成功连接，或显示与实际认证/服务器问题相符的错误，而不是权限导致的 `0x2000D`。
5. 打开“系统设置 → 隐私与安全性 → 本地网络”。
   - 预期：列表中存在 Farframe RDP，且开关处于启用状态。
6. 退出并重新启动 App，再次连接同一测试主机。
   - 预期：系统不重复询问，连接行为与第 4 步一致。

## 应记录证据

- App“关于”界面的版本号。
- 本地网络授权提示截图（遮盖任何环境信息）。
- 系统设置中 Farframe RDP 开关的截图。
- 连接成功或失败分类；如失败，仅记录脱敏错误码和阶段。

## 清理与恢复

- 删除测试连接，并确认对应钥匙串凭据和该连接的证书信任记录一并删除。
- 如需恢复未授权状态，在系统设置中关闭 Farframe RDP 的本地网络访问，或使用测试机支持的系统隐私重置方式。
